# Phase 3 — Application and Transfer

## Purpose

Test whether the learner can independently use, explain, recognize, and delimit the new concept. The worked example is not evidence of learner capability.

## Announce the phase

```text
PHASE: APPLICATION AND TRANSFER
LEARNING TARGET: <target>
YOUR CURRENT TASK: <one fresh independent problem>
```

## Required evidence sequence

1. **Procedural application:** can the learner carry out the canonical method accurately when procedure matters?
2. **Conceptual explanation:** can the learner explain why important components are necessary?
3. **Near transfer:** can the learner apply the same structure with different surface details?
4. **Discrimination:** can the learner recognize a case where the concept should not be used?
5. **Far transfer:** can the learner recognize the structure in a less obvious context? Use when calibrated and worthwhile; otherwise record a future retrieval task.

One well-designed problem may yield several forms of evidence. Still ask one primary learner task at a time.

Near transfer is mandatory before cycle completion. Far transfer is not an end-of-lesson ornament: use it only when it tests recognition rather than exhaustion. Delayed far transfer is often stronger evidence than immediate resemblance-based success.

## Respond to an error diagnostically

Before giving the answer, determine whether the issue is:

- missing conceptual understanding;
- incorrect procedure;
- failure to recognize relevant structure;
- task misinterpretation;
- overload or poor problem design;
- a missing prerequisite.

Use a focused mini-cycle when the error exposes a meaningful conceptual gap: let the learner generate around that gap, then consolidate it explicitly. For a local slip, give precise correction without restarting the whole protocol.

## Update durable artifacts

After the completion gate below is satisfied:

- complete the active cycle ledger;
- create a completed learning record using [the learning-record format](formats/learning-record.md);
- update a learning map only if the result changes target sequencing;
- add glossary terms only when the learner demonstrated their meaning;
- create a polished retrospective HTML lesson only if it will serve later retrieval or transfer.

Do not mark mastery based on agreement, confidence, an explanation the tutor supplied, or a single heavily scaffolded response.

## Completion gate

Set the cycle to `complete` only when:

- an independent near-transfer attempt exists;
- the learner's explanation reveals conceptual understanding or clearly delimits what remains uncertain;
- procedural issues are distinguished from conceptual ones;
- discrimination or applicability boundaries have been checked when relevant;
- remaining uncertainty and a recommended next target are recorded;
- any far-transfer claim is supported by an actual attempt.

At a later session, use a fresh retrieval or transfer problem before reteaching and update the record from the result.
