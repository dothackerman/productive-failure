# Designing a Productive Failure task

Use this with Phase 0. The task determines whether failure is preparatory or merely frustrating.

## Select one bottleneck

Target one meaningful concept or capability the learner has not fully learned. Make the target concept necessary to resolve the problem, not decorative. If the journey has several targets, record a provisional learning map and select only the current bottleneck.

## Check the prerequisite boundary

The learner needs enough related knowledge to make meaningful progress without already knowing the canonical account. Probe with a small use task, not a self-rating alone. If the learner cannot interpret the problem or produce any relevant move, teach the smallest prerequisite and verify it before designing the PF task.

## Task quality checklist

A suitable task:

- is understandable from the learner's current knowledge;
- requires genuine reasoning and admits progress without the target instruction;
- supports multiple plausible RSMs where the domain naturally permits them;
- has an authentic or curiosity-provoking purpose;
- states goals, information, constraints, and success conditions clearly;
- makes critical conceptual features consequential;
- provides situational feedback through tests, cases, outcomes, predictions, simulations, or consistency;
- is challenging without depending on a trick or hidden tutor intent;
- fits the agreed time, turns, technology, and safety constraints.

Do not enforce several RSMs where one rich approach and a meaningful revision provide enough contrast.

## Design situational feedback before presenting the task

Identify how the learner can challenge an approach without being told the answer. Examples include:

- a boundary case;
- an observed outcome;
- an executable test;
- two requirements that a proposal must satisfy simultaneously;
- a counterexample the learner can construct;
- a simulation with manipulable inputs;
- an internal consistency check;
- a contrasting case that the same method should classify differently.

Feedback must preserve generation. If a prompt uniquely reveals the next canonical step, it is instructional guidance and belongs in Consolidation.

## Preflight questions for the tutor

Before launching Generation, answer privately:

1. What prior knowledge could produce plausible RSMs?
2. What critical features should attempts make visible?
3. What variations are meaningful rather than cosmetic?
4. What situational feedback can expose affordances and constraints?
5. What evidence will show that further generation has saturated?
6. What canonical components can later be assembled from likely attempts?
7. What independent near-transfer task will test the underlying structure?

If these questions have weak answers, redesign the task rather than blaming the learner.
